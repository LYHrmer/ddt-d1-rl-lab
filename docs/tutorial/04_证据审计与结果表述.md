# 04：从回执、曲线和原生轨迹审计结果

本章只读取已有证据，不启动仿真、推理或训练。示例是第一轮 03b 自训 PPO：训练按计划完成，接口核验通过，但三条固定低速任务 **0/3 通过**。截至本章写作时，03c 第二次 pilot 正在训练，尚无最终能力评测；正式 B/R/M × 3 个训练 seed 未启动。下文不会把静态检查、视频或训练奖励写成任务通过。

## 1. 先确定你在审计哪一个模型

从[训练回执](../../evidence/career_contract_03/pilot03b_01/result.json)与同目录 `protocol.json` 读任务版本、seed、完整步数、源码/场景 SHA；从[导出 metadata](../../evidence/career_contract_03/pilot03b_export_01/metadata.json)读 ONNX SHA 和训练来源；再看评测和 C++ 运行回执是否引用**同一个**模型。03b 训练回执为 `COMPLETE`、seed 101、1,048,576 policy transitions 与 10,485,760 native 步。这个状态证明计划训练已完成，不证明策略会执行命令。

先读体积小的汇总文件，不要一开始就把完整 JSONL 或视频当作结论：

```bash
rtk read /home/lyh/ddt_ros2_ws/evidence/career_contract_03/pilot03b_training_summary_01/summary.json
rtk read /home/lyh/ddt_ros2_ws/evidence/career_contract_03/pilot03b_python_eval_01/summary.json
rtk read /home/lyh/ddt_ros2_ws/evidence/career_contract_03/pilot03b_onnx_pair_comparison_01/report.json
```

每份报告要同时读 `status`、实际计数、模型/配置身份和适用范围。`status=COMPLETE` 是数据采集完整；`status=PASS` 在离线核验里是数值一致；只有固定任务的所有门槛通过才是低速控制资格。任务序列、窗口和阈值见[合同 03](../career_execution_contract_03.md)。若文件 SHA 不一致，先停在来源核查，不拼接不同训练轮次的好指标。

## 2. 曲线说明训练过程，固定评测决定能力

[03b 训练汇总](../../evidence/career_contract_03/pilot03b_training_summary_01/summary.json)记录 256 个 rollout、最后 100 个 episode 平均 19.5672 秒、平均 reward 53.8617，其中 95% 到了 20 秒时间上限。可查看[诊断曲线](../../evidence/career_contract_03/pilot03b_training_summary_01/training_diagnostics.svg)和原始 `run_0_curve.csv`；该 CSV 的 256 行记录训练 transitions、吞吐与内存，不是固定命令下的速度误差。20 秒存活和奖励上涨是训练现象，不能代替前进、倒车和转向任务。

[Python 固定评测汇总](../../evidence/career_contract_03/pilot03b_python_eval_01/summary.json)报告 3 个 episode 均已记账、合计 14,980 native 步，但 `zero_delay_nominal_pass_count=0`。[逐任务记录](../../evidence/career_contract_03/pilot03b_python_eval_01/episodes.jsonl)给出失败位置和门槛：

| 序列 | 实际观察 | 未通过的具体门槛 |
|---|---|---|
| 前进后停车 | 298 policy tick、2,980 native 步后在 5.96 秒提前终止；移动稳态 vx MAE 约 0.029 m/s | 未完成 12 秒、倾倒；停车段尚未发生，停车末速和位移记为 `null`，不能当作 0 |
| 倒车后停车 | 完成 12 秒；末秒水平速度约 0.0122 m/s | 停车位移 0.0870 m，大于 0.05 m 门槛 |
| 正反转后停车 | 完成 12 秒；末秒角速度约 0.0055 rad/s | 稳态 yaw-rate MAE 0.1964 rad/s，大于 0.08 rad/s 门槛 |

前进的 `J` 约 102.25 含预先固定的 100 分提前失败罚分，不能与倒车的 0.254、转向的 0.627 当作同长度无惩罚轨迹直接比较。先看 `failure`、`threshold_flags` 和实际时长，再解释综合分数；缺失的停车指标保持缺失。每个 `.npz` 是该次策略的压缩逐 policy 轨迹，`episodes.jsonl` 中的 `trace_sha256` 可核对它的身份。

## 3. 数值一致性通过后，继续检查原生失败轨迹

[C++ ORT 1.10 golden 回执](../../evidence/career_contract_03/pilot03b_cxx_golden_01/report.json)对该 03b ONNX 做了 64 次**零物理**动作核验，最大绝对误差约 `4.17e-7`。报告里内嵌的 `schema.interface_id` 仍为旧 `d1-selftrained-pilot03-v1`，所以这份文件只能证明该 ONNX 在 C++ ORT 的离线动作值一致，不能单独当作 03b 运行时 schema 证明。另看[500-native 闭环对照](../../evidence/career_contract_03/pilot03b_onnx_pair_comparison_01/report.json)：它核对 03b 行为接口、schema、初态、动作和力矩，Python/C++ 的 qpos 最大绝对差约 `2.42e-14`、qvel 约 `1.73e-12`，并记录双方各 500 native 步。这仍只是一秒配对，不是 12 秒任务成功。

[C++ 前进试次](../../evidence/career_contract_03/pilot03b_deployment_plan_01/trial01_forward_stop/report.json)与[离线评分](../../evidence/career_contract_03/pilot03b_deployment_plan_01/score01_forward_stop/report.json)都记录 2,980 native 步后 `FALL`，评分 `evidence_valid=true`、`status=FAIL`；离线评分本身新增物理步数为 0。[原生 JSONL](../../evidence/career_contract_03/pilot03b_deployment_plan_01/trial01_forward_stop/trace.jsonl)每行对应一个 2 ms native 步，最后时刻约 5.96 秒、倾角 0.60484 rad，越过 0.6 rad 终止阈值。此试次的非法机体支撑标记与实际力矩饱和行数均为 0；RR thigh 实际角度从 2 秒约 1.434 rad 增至 4 秒约 1.784 rad、终点约 2.102 rad，而默认角为 0.8 rad。3–5 秒间该关节 issued action 约 77% 的 native 行处于 +1 截幅。这些值支持“姿态漂移和动作截幅伴随跌倒”的诊断，不足以单凭相关性证明唯一原因，也不能把动作截幅说成力矩饱和。

可用下面的只读命令复核末行和计数；它只解析现有 JSONL：

```bash

```

[失败视频回执](../../evidence/career_contract_03/pilot03b_failure_video_01/render_report.json)把这 2,980 行记录重放为[预览图](../../evidence/career_contract_03/pilot03b_failure_video_01/preview.png)与 `runtime_trace.mp4`：`source_terminal_reason=FALL`、`new_physics_steps=0`。视频帮助人看清姿态变化；它没有重新执行控制、不能独立认证结果。要查精确阈值和时刻，回到原生轨迹和评分回执。

## 4. 失败定位时按证据层级缩小范围

若离线 golden 不一致，先查 ONNX 输入名/维度、历史帧顺序、动作限幅、ORT 版本和模型 SHA；暂不要解释成“策略没学会”。golden 一致而 500-native 对照不一致时，再查 reset 初态、`qacc_warmstart`、2/10 原生步调度、PD 力矩与传感器刷新。若两者一致、固定任务却失败，就读 `episodes.jsonl` 的首个失败门槛，并对照原生 qpos/qvel、命令、issued/executed action、倾角、接触和力矩饱和。03b 正属于这最后一类：前进提前跌倒，倒车停车超距，转向跟踪不足。03c 的任务改动已经在[03c 合同](../career_execution_contract_03c_addendum.md)中提前冻结；训练后的结果需要新回执，不能改写 03b 的失败记录。
