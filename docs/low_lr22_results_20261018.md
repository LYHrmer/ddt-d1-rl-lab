# 22低学习率候选：真实结果与课程分布复核

22完成了训练、导出、64行C++数值核验及原36场景采集，但未保留原control的名义倒车停车能力，不能推广或替换模型。原17为27/36通过，22为18/36；零延迟从9/9降至6/9。低学习率缓解了更新幅度，却没有解决资格退化。

本记录只分析已有工件，没有加载模型、推理、训练或执行物理。完整逐对指标、阶段贡献及工件SHA见[机器可读报告](../reports/low_lr22_results_20261018.json)。旧17、18、21、22源码和现场均未改动。

## 下一候选的证据顺序

1. **先检验显式更新约束。** 若再安排一个候选，可从原control+Adam独立起步，保持22的seed181、LR1e-4、262144预算及全部课程，仅新增明确`target_kl`，例如.005。现有三个真实checkpoint的ZIP内JSON均为`target_kl=null`；实际训练代码已支持在backward/optimizer前停止过大KL更新。22末16行平均approxKL=.02163、clip fraction=.218，虽明显低于18的.15264/.536，仍不能保证保留原行为。该候选只测试保护措施是否足够；局部KL门也不保证最终模型相对原模型的全局距离。
2. **seed101同预算作为分布诊断。** 其他设置与22相同，仅换seed，能检验对seed181那组命令／reset样本的依赖。新的seed101会从新worker流起点开始，不能伪称续接原worker回合序号。若仍倒车停车退化，seed181就不是必要原因；若通过，一次训练seed也不能证明更广泛优越。
3. **课程调整应先针对顺序与停车上下文。** 只有进一步支持该假设时，才固定正负先行及撤令后时长的精确计数；当前不支持盲目提高负vx运动概率。课程变化应保留原阈值，若声称其因果效应，还需等预算、同起点对照。

这些是可证伪提案，本次分析没有执行新训练。后续方案使用独立新源、新预算、新输出、final-only、不重试；零延迟9/9无退化是必要门，随后完整原36，再按条件进入holdout。22同时降低LR至1/3并把新增预算缩至18的1/4，不能把结果表述为单变量LR因果实验。
