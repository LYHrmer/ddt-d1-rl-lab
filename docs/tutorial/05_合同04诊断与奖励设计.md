# 合同 04：从离线诊断到奖励设计的两次可证伪实验

本章讲的是一次完整的"诊断 → 单一假设 → 预注册 → 实验 → 判定（含被推翻）"闭环。**两次实验的控制资格都是 0/3**，本章的价值在方法与已查明的机制，不在成绩。结果与全部回执见[合同 04 结果](../career_execution_results_04.md)。

## 1. 为什么不能直接"再训一次、调调奖励"

合同 03 做了三次训练，资格 0/3、0/3、1/3。朴素做法是继续调权重重跑，但这样做无法回答"改善是来自改动还是来自随机性"。合同 04 用的纪律是：

1. **先离线诊断**，只用已有的冻结轨迹，新增 0 物理步、0 transitions；
2. 从诊断里**只选一个有证据支持的可证伪假设**；
3. 训练前**冻结**全部输入 SHA256、预算上限、验收门槛与**预注册预测**，写成回执；
4. 做**零积分静态检查**，确认"只改了一项"且新项的形状、梯度范围、最坏代价都在预期内；
5. 执行一次有界训练，不续训、不换 seed、不挑中间 checkpoint；
6. **按预注册预测判定假设，按原门槛判定资格，两者分开记账**；
7. 预测不成立就记"被推翻"，不调权重重跑后宣布成功。

这套纪律的实际作用：04b 的假设最终**被自己的预注册预测推翻**，而且因为预测是事前写死的，这个结论无法被事后改写。

## 2. 离线诊断：先把事实和假设分开

全部来自已有 npz 与 trace.jsonl 的重算。工具：`tools04/analyze_pilot_traces04.py`、`tools04/reward_signal_probe04.py`、`tools04/characterize_stop_oscillation04.py`。

**事实 1：奖励里没有被考核量的量纲。** 03 的 11 个奖励项全是瞬时量，而失败门槛考的是 8→12 s 的四秒积分位移。

**事实 2：轮动作幅值不受任何约束。** `leg_pose_deviation` 按 `task03c.py:24-25,113` 显式排除索引 3/7/11/15（四个轮）；`action_rate` 只罚变化量；`torque_sum_squared` 权重 −1e-5。

**事实 3：`standstill` 奖励在刹车段数值为零。** `exp(−v²/0.0004)` 在 v=0.1965 时是 1.2e-42。训练中实测该项全程仅满值的 0.4–1.0 %。这解释了为什么"增加零命令曝光量"（03c→03d 的改动）把蠕动降了 3–5 倍却没解决问题：**瓶颈不是曝光量，是奖励形状。**

**事实 4：03d 倒退任务的 PASS 有相当成分来自欧氏度量抵消。** 欧氏位移差 4.93 倍，但路径长度只差 1.39 倍；倒退先向后冲 0.0262 m，再被同一个正向偏置推回 0.042 m。**同一缺陷在两种符号下被同一个度量区别对待。**

这一条是本章最该记住的：**通过了一个门槛，不等于这项能力成立。** 要同时看路径长度、符号反转次数和分段位移，才能判断是真的停住了还是两个错误互相抵消。

## 3. 04a：位移锚定 —— 主判据成立，但代价是振荡

**唯一改动**：零命令段内对"离该段起点的 XY 位移"加 Huber 惩罚（`training/d1_rl/task04a.py`）。

**预注册预测**：P1（主判据）turn_stop 位移 < 0.05 m；并**事前声明不预测** turn 的 wz MAE 会达标，也**事前声明不预期达到 3/3**。

**结果**：P1 **成立**（0.06076 → 0.03485）。零令净轮速目标从 +0.460 降到 +0.115 rad/s，而且**主动刹车首次出现**（净轮速目标为负的 tick 占比 0.0 % → 45.8 %）。turn 的沿航向净前进从 0.060 m 降到 0.00017 m。

**但资格从 1/3 退到 0/3**，因为出现了一个新失败模式：

| 11–12 s | 03d forward | 04a turn |
|---|---:|---:|
| vx 主频 | 1.0 Hz（幅值 ~0） | **12.0 Hz** |
| 净轮速目标标准差 | 0.060 rad/s | **0.976 rad/s** |
| 路径/欧氏位移 | 1.00 | **4.48** |
| 质心摆幅 | — | **1.08 mm** |

12 Hz 远低于 50 Hz 策略率的 Nyquist，**振荡是策略主动指令出来的**。它使三条任务的末秒水平速度门从全部通过变成全部失败。

**为什么策略会这样选？** 用 04a 自己的权重算代价：单向蠕动约 −1.83 /s，极限环约 −0.89 /s —— **振荡更便宜，是奖励设计让它成为最优解**。

**更深一层（这是本章的关键教训）**：查 `training/d1_rl/interface.py:81-85`，57 维观测 = 滤波陀螺 + 机体重力方向 + 命令 + 关节偏移（轮项强制为 0）+ 关节速度 + 上次动作，**没有基座位置，也没有基座线速度**，历史只有 200 ms。所以"离锚点的位移"**对 actor 根本不可观测**。

> 给一个无记忆、观测不到目标量的策略去优化该目标量，它会找到一个退化的代理行为。本例中是高频抖振 —— 保持"时间平均位置不动"的唯一无记忆实现方式。
>
> **设计奖励前先问：这个量，策略看得见吗？**

## 4. 04b：轮动作幅值 —— 被自己的预注册预测推翻

04b 与 04a 是**同胞而非后继**：两者都在同一个冻结的 03d 基线上**各加一项**，差别只在被测量。这样对比隔离了"被测量选择"这一个变量。

**选择理由**（接口算术，`schema03d.json` + `robot.xml`）：轮 kp=0、kd=0.5 N·m/(rad/s)、r=0.087 m、整车 48.15 kg ⇒ 轮动作为零就是一个纯阻尼器，预测 τ=0.195 s、从 0.1965 m/s 刹停 0.0383 m，**同时满足 0.05 m 位移门与 0.02 m/s 末秒速度门**。而且这个被测量是策略自己的输出，**完全可观测**，不会重复 04a 的失效路径。

**静态检查在训练前拦下一个真实缺陷**：第一版饱和点设 0.09，但实测 04a 的逐 tick mean(a²) 是 0.174、初始化时约 0.135，**都在梯度平区内**。新增的 `gradient_live_over_the_measured_range` 检查抓住了它，饱和点改到 0.25（失败回执 `task04b_static_01` 原样保留）。

> 零积分静态检查不是形式主义。本合同它两次在花掉 1,048,576 transitions 之前拦下真实缺陷（另一次是 04a 启动器的无限递归，0 积分、未扣额度）。

**结果**：

| 判据 | forward | reverse | turn | 判定 |
|---|---:|---:|---:|---|
| P2 零令 mean(a²) < 0.02 | **0.00099** | **0.00098** | 0.0236 | 完成的两条达标（03d 0.065、04a 0.174 → 降 65–175 倍） |
| P3 净轮速目标 std < 0.20 | **0.00188** | **0.00219** | 0.110 | 完成的两条达标（04a 0.976 → 降约 500 倍，抖振消除） |
| P1 位移<0.05 且 末秒速度<0.02 | 位移 0.0753 ✗ | **两项全达标** | 跌倒 ✗ | **NOT_MET** |

**假设 REJECTED，资格 0/3，含 1 次跌倒**（turn 在 11.16 s 跌倒，峰值 roll/pitch 0.5516 rad）。另有一个新退化：驱动相 vx MAE 退到 0.068/0.070，越过 0.06 门槛。

**04b 唯一的亮点**：reverse_stop 通过 8 项门槛中的 **7 项**，含**真正通过**（路径/欧氏比 1.73，不依赖抵消）的位移门，并经独立 C++ 运行器复现到 8 位小数。唯一失败是驱动相 vx 跟踪。**这是单条任务成绩，不是资格通过。**

## 5. 合同强制的那次测量：被自己的间接估计骗过

04b 合同第 8 条事前写明：

> 若同时 P2/P3 成立（轮动作确实被压到近零）而 P1 仍不成立，则接口算术本身有误，**必须重新测量刹停距离而不是继续调奖励**。

实际落在这个分支上。过程值得完整复述，因为中间出过一次错：

**第一步（离线拟合，错的）**：在 04b 轨迹里取"轮动作近零"的 tick 拟合速度衰减，得 τ=0.84–1.63 s，即阻尼比预测**弱 4–8 倍**。看起来结论是"门槛不可达"。

**第二步（开环探针，350 native）**：腿动作固定为 0 时整车 60 ms 内从 0.457 m 沉到 0.432 m，0.7 s 被非法体支撑终止。⇒ 算术背后"刚体直立、四轮均载"的前提不成立，但没测到刹停距离。

**第三步（策略在环探针，1,650 native）**：腿由策略正常控制，**只把四个轮动作强制为 0**：

| 指标 | 实测 |
|---|---:|
| 释放速度 | 0.0883 m/s |
| **刹到 \|v\|<0.02 的距离 / 时间** | **0.00733 m / 0.16 s** |
| 同速下算术预测 | 0.01720 m |
| 判定 | **门槛内，且阻尼比预测强约 2.3 倍** |

**第一步的结论是错的。** 那次拟合取到的是刹停后的回弹/游走段（速度降到 0.0076 后反弹到 0.0296 m/s），不是自由滑行。

> 从一段轨迹里拟合物理参数，先确认这段轨迹处在你以为的那个物理状态里。能做受控探针就别拟合。

**所以 04b 失败的真正定位**是：零轮动作足以在门槛内刹停，但**策略在刹车窗口内并没有归零** —— forward 的 8–9 s 实测 mean(a²)=0.02208、净轮速目标 +0.4596 rad/s，是 11–12 s（0.00099）的 **22 倍**，而该窗口贡献了总位移的 70 %。策略只在"已经停住之后"才归零。

两个必须声明的限制：释放速度只有门槛相关速度的 45 %（外推到 0.1965 m/s 约 0.016 m，**是外推不是实测**）；回弹段是强制覆盖造成的动作不一致，不能据此断言腿是独立漂移源。

## 6. 工程纪律：不改冻结文件也能换实现

`tools/train_d1_ppo.py` 与 `tools/evaluate_d1_ppo.py` 是 03d release 的冻结输入，但它们硬编码 `from d1_rl.factory03 import environment_class`。做法不是复制 650 行，而是 `tools04/run_frozen_entry.py`：

1. 先校验冻结脚本 SHA256 等于 release 记录值；
2. 把 `factory03` 的两个查找函数替换为新 factory 的版本；
3. 用 `runpy` 把冻结脚本**作为 `__main__`** 执行。

第 3 步的"作为 `__main__`"是必须的：`SubprocVecEnv` 用 forkserver，cloudpickle 对 `__main__` 里的闭包按值序列化、对可导入模块的函数按引用序列化，所以子进程会 import 注入的 factory 并构造正确的任务类。静态检查里的 `forkserver_worker_resolves_04b_task` 就是在验证这条路径。

同理，`factory04b` 以**委托链**扩展 `factory04`，而不是修改它 —— 后者的 SHA 已写入 04a 的冻结回执，改了就会让 04a 的身份失效。每个合同只加一个不可变的链节。

另外修掉了 03 遗留的 ROS 启动缺陷：`runtime03/prepare_pilot_deployment03.py:79` 手写 `PYTHONPATH` 只设了 `local/lib/python3.10/dist-packages`，丢掉了 `rpyutils` 实际所在的 `/opt/ros/humble/lib/python3.10/site-packages`。新入口 `runtime04/launch_env04.sh` **只做 source、不覆盖 `PYTHONPATH`**，导入预检 11/11 PASS。回执显式记录 `watchdog_validated: false` —— **导入通过不等于 watchdog 通过。**

## 7. 预算与如实记账

两次训练各 1,048,576 transitions / 10,485,760 native，合同 04 新增合计 **2,097,152 transitions / 21,022,770 native**，全项目累计 **52,914,120 native**。各池分别记账，失败步也计入，详见[总账](../../evidence/career_contract_04/final_delivery_01.json)（由 `tools04/build_final_ledger04.py` 从回执里重算，不抄文档）。

**一次如实记录的预算损失**：策略在环探针第 1 次尝试物理循环已跑完、`env.close()` 已完成，随后在构造回执时因 `Path.relative_to` 对相对路径抛异常而崩溃，**输出目录尚未创建、计数器随进程丢失**。实际消耗未知，按计划上限 1,650 native 保守计入并视为该池耗尽；这是工具缺陷造成的损失，**不是测量结果**，不据此声称任何物理结论。重跑前先用 20 native 冒烟验证回执写入路径。

> 预算损失要写进总账。能计的按实际计，不能计的按上限保守计，并写清为什么不能计。

## 8. 本章的可迁移结论

1. 设计奖励前先确认**被测量对策略可观测**；不可观测的目标会得到退化的代理行为。
2. **通过一个门槛不等于能力成立** —— 同时看路径长度、符号反转和分段分解，排除错误互相抵消。
3. 零积分静态检查要覆盖**实际运行态**（含注入、含子进程），而不只是"看起来对"的未注入态。
4. 能做受控探针就别从轨迹拟合物理参数；拟合前先确认该段处在你以为的物理状态。
5. 预注册预测把"假设判定"和"资格判定"分开，使"假设成立但资格更差"（04a）和"假设被推翻"（04b）都能被如实记录。
6. 不改冻结文件也能换实现：SHA 校验 + 依赖注入 + `runpy` 作为 `__main__`，并用委托链而不是修改上游。

## 9. 仍未完成（不得预写成功）

平地三条任务的整体资格（当前最好为单条 7/8 项）、转向增益不对称（四版本一致未达标）、04b 的两个新退化、真实 ROS 停发后的物理停稳、自训策略的丰富地形通过与真实 15 mm 台阶跨越、持续侧移、1.5 m/s、正式三臂×三 seed、物理自救、实机验证。

下一步的证据方向已明确（针对命令切零后的前若干 tick，而非整个零令段），但**需要新的可证伪假设与新的有界合同**。
