## 1. 固定 Python 环境

本机项目依赖装在仓库的 `.python-deps`，入口脚本 `run_training03.sh` 固定使用 `/usr/bin/python3`、该目录和 `training` 包路径。已核对版本为 Python 3.10、NumPy 2.2.6、MuJoCo 3.3.0、Gymnasium 1.2.0、stable-baselines3 2.7.0、PyTorch 2.12.1、ONNX 1.18.0、Python ONNX Runtime 1.23.2、psutil 5.9.0。C++ 运行器另用 MuJoCo 3.3.0 与 **ORT 1.10.0**；Python ORT 通过不能代替 C++ 检查。

在**干净副本**安装项目隔离包时，先确保 Python 3.10 和 pip 可用，再执行（PyTorch 下载量较大，本仓库现有 `.python-deps` 不需重装）：

```bash
rtk proxy /usr/bin/python3 -m pip install --target /home/lyh/ddt_ros2_ws/.python-deps "numpy==2.2.6" "mujoco==3.3.0" "gymnasium==1.2.0" "stable-baselines3==2.7.0" "torch==2.12.1" "onnx==1.18.0" "onnxruntime==1.23.2" "psutil==5.9.0"
rtk proxy /home/lyh/ddt_ros2_ws/run_training03.sh -c 'import gymnasium,mujoco,stable_baselines3,torch,onnx,onnxruntime; print(mujoco.__version__,gymnasium.__version__,stable_baselines3.__version__,torch.__version__,onnx.__version__,onnxruntime.__version__)'
```

版本行应显示 `3.3.0 1.2.0 2.7.0 2.12.1 1.18.0 1.23.2`；PyTorch 版本可能额外带本机 wheel 后缀。若版本不同，先修依赖，不能用系统默认 MuJoCo 3.12 跑一半再称与 C++ 物理一致。下面的 `--help` 均只解析参数，不积分：

## 2. 训练入口：先 pilot，再决定是否正式训练

启动前先核对 03b 的预算登记、离线接口对照、固定动作诊断和跨语言动态配对回执；[合同 03b](../career_execution_contract_03b_addendum.md)给出硬门和各预算池。pilot 使用独立 seed 101，从随机权重学习，不能加载同事策略、03a checkpoint 或固定静力动作。下面是 **B 臂零延迟**的一次示例；8 环境来自旧吞吐预检，但 03b 实际内存和吞吐仍须以本次记录为准。`--deadline` 是外部进程组墙钟看门狗，`--max-wall` 是训练器内部上限。

```bash
rtk proxy python3 -B /home/lyh/ddt_ros2_ws/tools/bounded_training_run.py --deadline 5440 -- --output /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_pilot03b_B101_01 --config /home/lyh/ddt_ros2_ws/training/configs/pilot03b.json --arm B --seed 101 --envs 8 --steps 1048576 --max-wall 5400 --kind pilot
```

这条命令会调用项目包装器，不需手动设置 `PYTHONPATH`。预算上限为 1,048,576 个 policy transitions，即最多 10,485,760 个 2 ms 原生物理步；提前跌倒的环境也要按实际积分记账。`result.json` 的 `status=COMPLETE`、`trained_transitions=1048576`、`inputs_unchanged=true` 才表示完整训练；`policy.zip` 只在完整状态下命名为该文件。`protocol.json` 保存随机初始化、模型/配置/源码 SHA 和超参数；`ledger.jsonl`、`live_status.json`、`env_*.counts.json` 记录吞吐、资源与真实 native/PD/policy 计数。训练完成仍不等于能站稳。

`ERROR`、`WALL_LIMIT`、`INVALID_PARTIAL_NATIVE_INTERVAL` 或看门狗截止都要保留原目录、`error.txt`/`result.json`/旁侧 `.watchdog.json`；不能把 `partial_policy.zip` 改名继续当完成模型。查看错误后只在事先允许的开发轮次内，用**另一个新目录**重跑，并将先前实际积分计入预算。若源文件/配置在训练后改变，导出器会拒绝 checkpoint 源身份；保留历史结果，不把旧模型标成新接口。

只有 pilot 的 Python、C++ 和停令回退门槛全过，才登记 `evidence/career_contract_03/formal_budget.json` 并跑 9 个正式模型：B 固定 0 ms、R 按 episode 随机 0/20/40 ms、M 固定 20 ms，各使用 seed 11、23、37。每个模型独立随机初始化且最终 transitions 一致；正式命令的 `--steps` 必须等于预算文件中的 `steps_per_run`，`--kind formal --formal-budget ...` 必填。不可把旧 03a B 臂与新 03b R/M 臂混成消融。

## 3. 导出：完成 checkpoint 才能变成 ONNX

以下命令仅在上面的 pilot 真正完整后运行；`--checkpoint` 只能指向该运行目录的 `policy.zip`：

```bash
rtk proxy /home/lyh/ddt_ros2_ws/run_training03.sh /home/lyh/ddt_ros2_ws/tools/export_d1_ppo.py --checkpoint /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_pilot03b_B101_01/policy.zip --config /home/lyh/ddt_ros2_ws/training/configs/pilot03b.json --output /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_export03b_B101_01
```

输出应有 `policy.onnx`、`metadata.json`、`golden_fixtures.json`。ONNX 输入是 `obs float32[1,57]` 与 `history float32[1,10,57]`，输出 `actions float32[1,16]`；导出的是 PPO 高斯演员的确定性均值并限幅到 ±1，没有 VecNormalize。导出器检查 64 个固定样例的 Torch / Python ORT 绝对动作误差 ≤1e−5，使用 opset 11、IR 7；`metadata.json` 写入模型、配置、03b 接口、动作尺度、训练来源及各文件 SHA。这里不加载 MuJoCo，也不积分。若报源哈希、架构或 Python ORT 不匹配，先保留失败现场；不要只改 metadata 或降低误差阈值。

再用**真实 C++ ORT 1.10** 对同一 64 个样例独立复核。先从 `metadata.json` 的 `sha256.policy_onnx` 复制完整 64 位值，替换命令中的 `POLICY_SHA_FROM_METADATA`；输出目录仍需是新名字：

```bash
rtk proxy env LD_LIBRARY_PATH=/opt/ros/humble/lib:/home/lyh/ddt_ros2_ws/install/mujoco/lib /home/lyh/ddt_ros2_ws/runtime03/build/d1_runtime03 --onnx-golden /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_export03b_B101_01/golden_fixtures.json --policy /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_export03b_B101_01/policy.onnx --expected-policy-sha256 POLICY_SHA_FROM_METADATA --output /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_cxx_golden03b_B101_01
```

`report.json` 应记录 64/64 比对及实际最大误差 ≤1e−5、零物理步。旧 03a 的离线通过回执不能代替这个新模型的检查。

## 4. 评测：先开发集，再独立正式集

pilot 评测固定为前进停车、后退停车、正反转停车三条 12 秒序列，各用 seed 7001、0 ms 额外延迟，共 3 episode，最多 18,000 原生步。命令阶段由脚本冻结：平移为 0–2 秒零令、2–8 秒 ±0.2 m/s、8–12 秒零令；转向为 2–5 秒 +0.2 rad/s、5–8 秒 −0.2 rad/s，其他时段零令。**这会推进物理**，只在预算已登记时运行：

```bash
rtk proxy /home/lyh/ddt_ros2_ws/run_training03.sh /home/lyh/ddt_ros2_ws/tools/evaluate_d1_ppo.py --onnx /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_export03b_B101_01/policy.onnx --config /home/lyh/ddt_ros2_ws/training/configs/pilot03b.json --phase pilot --max-episodes 3 --max-native-steps 18000 --output /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_evalpilot03b_B101_01
```

评测器在加载 ONNX 时核对 metadata 的配置/机器人/接口/旧审计 schema、动作尺度和 64 个 golden fixtures 的 SHA。每个 episode 保存压缩 `.npz` 轨迹，`episodes.jsonl` 给出 J 分项、跌倒/非法承载、稳定段误差、停车指标和真实步数；`summary.json` 汇总 3 条。任一提前结束计 `FAIL` 并加固定失败罚分，不会因为跑得短就取得低误差。`summary.status=COMPLETE` 只表示计划的 episode 都有报告，**仍须检查** `early_failures` 与全部门槛；不能把它单独当作策略通过。

正式独立评测须待三臂九个完整模型和预算冻结：每模型 3 序列 × 3 个 reset seed（1001/1002/1003）× 4 个执行延迟（0/20/40/60 ms）=36 episode，`--phase formal --max-episodes 36 --max-native-steps 216000`，每个模型使用新的 `my_evalformal03b_臂_seed_序号` 输出目录。60 ms 是训练范围外压力测试，单独报告。比较 R/B/M 时以**3 个训练 seed**为统计单元，不把 36 个 episode 当成 36 个独立训练样本。丰富地形尚需另一套接触与越障试验；本章平地成绩不能转写成台阶通过率。

## 5. 部署入口及证据界线

新运行器见 [`runtime03/README.md`](../../runtime03/README.md)。先用 `--validate-only` 做零积分身份和静态初态检查，再在已登记的 C++ 试次预算内运行 `--mode replay` 或 ROS `--mode live`。运行时需要 03b 专用 `runtime03/schema_pilot03b.json`；从文件算出 schema SHA，从训练场景算出 XML SHA，从导出 metadata 取 ONNX SHA，分别填入三个 `--expected-...-sha256`，不可互换。运行器对命令超时 0.5 s 请求零速，记录真实 native/PD/policy 时刻、推理时延与停止原因；这些运行时保护和停稳效果也须分别验收。

```bash
rtk proxy sha256sum /home/lyh/ddt_ros2_ws/runtime03/schema_pilot03b.json /home/lyh/ddt_ros2_ws/src/ddt_ros2_control/urdfs/d1_description/mujoco/scene_contract_plane_02.xml
rtk proxy env LD_LIBRARY_PATH=/opt/ros/humble/lib:/home/lyh/ddt_ros2_ws/install/mujoco/lib /home/lyh/ddt_ros2_ws/runtime03/build/d1_runtime03 --schema /home/lyh/ddt_ros2_ws/runtime03/schema_pilot03b.json --model /home/lyh/ddt_ros2_ws/src/ddt_ros2_control/urdfs/d1_description/mujoco/scene_contract_plane_02.xml --policy /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_export03b_B101_01/policy.onnx --expected-model-sha256 MODEL_SHA_FROM_COMMAND --expected-policy-sha256 POLICY_SHA_FROM_METADATA --expected-schema-sha256 RUNTIME_SCHEMA_SHA_FROM_COMMAND --output /home/lyh/ddt_ros2_ws/evidence/career_contract_03/my_runtime_validate03b_B101_01 --validate-only
```

`--validate-only` 只证明身份和静态初始化；真正 12 秒回放需另一个新目录，去掉 `--validate-only` 并显式加 `--mode replay --sequence forward_stop --seconds 12 --max-native 6000`。该 C++ 预设序列与 Python 评测器的移动段长度不同，不能把两者指标逐项混算。ROS live 模式应在部署资格试次登记后再单独运行，不用旧 `flat_lab.onnx` 冒充本章自训产物。

训练为何要保存原始采样动作的 log-prob、历史为何不含当前帧、腿/轮动作怎样变成 250 Hz PD 力矩，以及 `terminated` 与 20 秒 `truncated` 的区别，见[观测动作与时基](02_观测动作与时基.md)。本章所有 `my_...` 目录都是**示例名**；再次运行时换一个新后缀，并先查对应预算是否仍有余量。
