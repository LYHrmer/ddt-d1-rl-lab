# 83：真实 C++/ROS 会话接线与策略目标冲突诊断

本轮把 82 的原生契约接到了原 C++34 actor 和隔离的 ROS2 DDS 通道，并完成三个固定模型的策略梯度诊断。**工程链路已通过本轮短测；没有新的策略性能资格、硬件资格或默认模型替换。** [机器摘要](../reports/project83_results_20261104.json)与原始证据一同发布。

方案先区分启动契约、传输故障和控制性能，再为每一类安排最小可判定验证。模型与 actor 权重不更新；不重跑归档 48，也不续跑 80/81 的失败候选。两仓共用的[五项预算计划](assets/project83/plan83.md)与[启动契约修订](assets/project83/revision83_engineering.md)保留完整内容。wheel 的传感器、MPC、PI 对照见[另一仓 83 报告](https://github.com/LYHrmer/wheel-legged-control-lab/blob/876053401d8663f2bc98cadb8244b80b7fbe38f8/docs/project83_control_20261104.md)。

## 1. 已修复的运行链路

新增 `runtime83/session83.hpp` 使用原 82 核心，明确记录 39 维合成观测、命令时间、627 维有效输入、序号、进程世代、推理尝试与完成数。保留 C++34 内部参考整形、历史堆叠、每回合新进程和原始动作契约。实际 actor、ONNX、C++34 源码和 ORT 库均按原 34 身份固定；未修改这些源或重新导出权重。

`runtime83/ros_checked83.cpp` 接通私有命名空间中的 packet → actor → effort → consumer。生产端与消费端分别检查截止时间：DDS 已发送的消息无法收回，消费端必须拒绝过期或撤销的授权。测试只有合成观测与虚拟 effort，不连接硬件，也不推进物理。

独立读回重新计算输入 SHA、标量参考整形、双进程复位、计数、截止与故障语义，**4,314 项核验全部通过**。这类算术与来源核验不等于 4,314 次独立控制实验。[完整运行轨迹](assets/project83/runtime83_raw.zip)、[独立读回](assets/project83/runtime83_independent_audit_01.json.gz)、[读回源码](assets/project83/audit_runtime83_checked.py)可核查。

## 2. 三模型一致发现：偏航下降与停车目标冲突

新增 `tools83/policy_geometry83_checked.py` 复用三个固定 75 control 模型（64001/64002/64003）和原 25 actor。只使用既有完整 D 轨迹，固定 21 个起点：81 偏航 6 点、80 前进 6 点、80 运动后停车 9 点；不访问 81 V/H 进行选参。停车是运动后零命令状态，不是冷启动站立。

在固定 H32 上，分别对 4 个轮动作输出行的 516 个头部参数求偏航、前进、停车目标梯度。**三个模型的纯偏航下降方向均会增加停车局部代理，两个还会增加前进局部代理。** 因此继续只提高偏航权重缺少依据。

随后求解确定性的两半空间投影：在前进和停车一阶变化不为正的约束下，选择距离纯偏航下降方向最近的方向。它借鉴多任务梯度冲突处理的思路，但实现是固定双约束投影，不是随机顺序 PCGrad 的复现，也不继承其性能结论。局部推导、预算和边界见[设计记录](assets/project83/policy_design83.md)。

| 固定模型 seed | 纯偏航方向与前进 / 停车冲突 | 投影保留的未归一化偏航下降量 | 归一化后、未施加的 0.009 步长局部 Q6 相对下降预测 |
|---|---|---:|---:|
| 64001 | 是 / 是 | 75.0462% | 0.424910% |
| 64002 | 否 / 是 | 40.8294% | 0.449643% |
| 64003 | 是 / 是 | 48.0972% | 0.493723% |

三个投影方向均非零，双约束与 KKT 检验在原数值容差内成立。第三列是未归一化量；同一 0.009 尺度下的下降保留比实际为 **72.298%、56.235%、74.782%**，两种量不能混用。作为另一项局部检查，0.01 行 L1 约束下不带保护的线性偏航上界分别为当前 Q6 的 **2.8790%、3.6128%、3.2376%**；这也不能证明有限非线性更新不可能达到原 5% 门槛。

所有上述变化都是学习模型的局部线性预测，**没有实际施加参数更新，没有端点、量化或物理收益验证**。保护的是前进 6 点均值和停车 9 点均值的一阶代理，不是每个状态都不退化。偏航 Q6 的 max 分支在全部 9 个 model×reset 上选择 tick 325，因此它也不能证明两个转向方向同时改善。

执行完整覆盖 **63 个 point×model、2,016 次 dynamics forward、2,016 次 actor-head forward，0 次参数更新、0 个物理步**。参数、缓冲和源梯度前后 SHA 不变；CPU **7.334789 s**。独立脚本核对 1,453 个来源绑定、70 个产物、9 条梯度共 4,644 个标量，完成 **3,330 项数值核验**，最大差 **5.55×10⁻¹⁷**。没有单 seed 排名，也没有把局部诊断当完整候选。[原失败及新完整记录](assets/project83/policy_geometry83_raw.zip)、[独立读回](assets/project83/policy83_independent_audit_01.json.gz)、[读回源码](assets/project83/audit_policy83_checked.py)均保留。

原失败目录、原计划和原入口没有覆盖或续跑。checked 入口保持原模型、数据、指标、门槛和总预算，先通过冷校验再封存；原生 64 次成功调用没有重复执行。原 `ros_probe83.cpp` 和 `policy_geometry83.py` 是保留的历史入口，使用新入口时应显式选择 checked 文件。

本机新增 **57 项测试通过**，含假 actor 的 **131 项原生断言**；冷 CLI 验证不会创建 actor、ROS context 或输出目录。新头依赖还单独编译验证。GitHub 新 `project83-model-free-contracts` 在 Python 3.10/3.12 下运行标量与假协议测试，不下载权重、不训练、不做物理；既有 static-checks 继续原样运行。CI 不构建 ROS 入口，实际 ROS 构建与短测由本机回执覆盖。

重任务按序运行于独立 systemd 单元：Nice10、单 CPU 亲和、数值库/ORT 单线程、MemoryHigh 2 GiB、MemoryMax 3 GiB、swap 0；DDS 有自己的中间件线程，不能声称只有一个操作系统线程。准入有效内存至少 4 GiB，运行保留至少 2 GiB；新增 PSI 压力准入与运行退出检查，子进程清理只针对所属 cgroup。策略诊断峰值 cgroup 内存 **0.9703 GiB**，有效可用内存最低 **4.7888 GiB**；无 high/max/OOM 事件。各阶段日志、失败和构建依赖回执见[工程证据包](assets/project83/engineering_receipts83.zip)。

[原冻结闭包复核](assets/project83/integrity_final83.json)和[checked 新闭包复核](assets/project83/integrity_checked_final83.json)均完整保留；wheel v27 SHA 仍为 `d3c38429362e82745179f2c526b2ee52d805526df390d52346c805e5a51fff09`。新头文件只补齐干净 checkout 的构建依赖；原实际运行仍由系统头编译，没有重写原构建或性能资格。

## 4. 剩余问题与下一步的判定顺序

1. 先针对真实传感器异步消息定义同步/过期契约，再验证带实际时间戳的回放。当前合成包无法回答这个问题，硬件控制接管不在本轮范围内。
2. 策略侧先解决多步响应可信度和每个任务的约束表达。当前投影只给出很小的局部代理改善，不能据此追加大训练或放宽原门槛；80/81 的候选仍拒绝。
3. wheel 侧相位一致采样共同完整配对的跟踪 RMSE 降低 24.32%，但新增一项配对跌倒；负载补偿高度偏差明显降低，姿态和用力仍退化。它们均未获得默认替换资格，具体数字与否决项见 wheel 报告。PI 的精确参考存在扭矩可行性缺口，也不能只靠增益修复。

本轮交付修复了入口、资源退出与真实传输的可验证工程问题，并把性能失败的原因缩小到可检验的机制。没有宣称 SuperMimic 思路已取得真实控制收益，也没有删除不利结果。
