# 合同 10 的冻结与一次执行链

第三轮交付将已批准预算变成可核验的独立实验链：[静态核验](../tools12/check_contract10_static.py)、[事前冻结](../tools12/release_contract10.py)、[一次执行编排](../tools12/run_contract10.py)、[证据判定](../tools12/verify_contract10.py)。科学配置和预算见[合同 10](career_execution_contract_10.md)。所有工具稳定、测试与历史保护核验通过后才生成 release；资源准入在真正 spawn 前重检。

机器可读计划的 `AUTHORISED_PENDING_FREEZE` 表示预算已确认，仍不能传给训练监督器执行。静态回执绑定计划、授权和全部冻结输入 SHA；release 只允许写入一次固定路径 `evidence/career_contract_10/scale10_release_01.json`，不覆盖旧合同或旧回执。原始所有者批准保存在授权 01，规范记录 02 绑定其 SHA、唯一尝试、禁止续训和最终 checkpoint 规则。

执行器默认输出计划，只有 `--execute` 才执行。它按 E0、正式训练/E1、数值导出、C++ 比对、三任务 checkpoint 资格评测、零积分重放、判定的顺序前进。E0 或正式训练失败立即停止物理步骤；正式训练不完整时，判定保存 Q1–Q5 不可评估。导出失败按事前规则保留失败，仍使用同一最终 `policy.zip` 完成资格评测，数值部署链独立报告。

每阶段启动前写 `execution_01/journal.json`；完成后绑定输出 SHA。再次运行只能读取已完成、身份一致的阶段。已经开始但缺乏完整回执的阶段拒绝自动重试；评测中断也不能重评。NOT_READY 没有创建训练输出/监督目录，允许将来重新检查资源条件。已知实际计数、未知余量与项目累计下界分别记录，未用预算不能变成重试许可。

判定要求同一 release 的完整监督回执、全部 worker 的完整计数、真实最终 checkpoint、评测协议和每份 NPZ 的 SHA。训练重放从原始 monitor 和命令生成规则重新构建每回合，std 从 progress 重算；不能通过更改提前终止标签或重放摘要改变 Q2。重复任务、其他权重、部分评测、阈值变动或断裂的证据链均拒绝。

这些工程门不承诺训练必然通过资格，也不把单种子中的同时变化解释为噪声中介因果的独立证明。

本机冻结前全套 **962 项测试通过**，其中 80 项静态核验测试和 85 项执行/判定定向测试；32 项既有静态检查、历史冻结输入、77 项保护文件与 9 份用户结果核验通过。当前判定器对合同 08 的 9,163 个真实历史回合和三份评测轨迹做只读重算，std、提前终止次数和资格结果均保持一致。62 项输入已通过真实静态核验并生成独立冻结回执，摘要见[准备回执](../reports/contract10_preparation.json)。冻结之后不再修改这 62 项输入；真实训练进度和控制结果将单独记录。
