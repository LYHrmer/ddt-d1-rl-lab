## 准入、冻结和等价性

启动前要求有效可用内存至少 **7 GiB**，有效值取宿主 MemAvailable 与可见 cgroup 硬上限余量的较小值；运行停止门仍是 **3 GiB**，不降低。资源不满足时只写 NOT_READY，0 物理步，不占唯一 spawn 机会。不会关闭用户应用来凑内存；准入只是检查，不声称资源独占。

## 预测和后续顺序

原 09 阈值保留：Q1 最后 1/4 平均动作 std < 0.45；Q2 最后 1/4 前进驱动段内提前终止 ≤ 15；Q3 最终资格至少 2 项；Q4 forward_stop 完整 12 s 不跌倒；Q5 只描述驱动末秒双向速度。基准仍是合同 08 的同种子 8 倍训练。

Q1/Q2 都成立，仅支持本种子的“去熵后噪声与前进退化同时改善”；Q1 成立而 Q2 不成立，说明压低噪声不足以改善前进；Q1 不成立，则熵奖励不是 std 上涨的主因。单变量去熵并未独立操纵 std，因此即使同时改善，也不把这当作噪声中介因果的单独证明。Q3/Q4 独立报告，不改变机制判读。

顺序为：零积分静态检查 → release → E0 → 正式训练/E1 → 单样本新导出入口 → 64 例 C++ 黄金比对（导出通过时）→ 冻结评测器三任务 → 离线训练回合重放 → 判定与总账。导出容差仍为 `1e-6 / 1e-5`。资格评测始终使用本轮完整训练的同一最终 `policy.zip`，通过冻结评测器的 `--checkpoint` 路径运行，保持与合同 08 的比较口径；不按导出结果切换推理实现。若导出失败，保留 FAIL、跳过 C++，部署数值链记未验证。任何结果都不放行正式三臂×三 seed。

新执行入口默认只列出计划，显式执行才进入监督器。每个真实步骤在启动前写持久 stage 记录，完成后绑定回执与工件 SHA；已尝试却缺乏完整回执的步骤不得自动重试。NOT_READY 只记录资源拒绝，未启动的步骤可在条件满足后再次准入。恢复编排只能读取已绑定的完整回执，不能恢复或重新训练、重评中断的真实步骤。评测若中断，记录已知计数和未知余量，不将缺失的末次计数当作零。
