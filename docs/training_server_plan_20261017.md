# 下一次训练的服务器需求估算

这是租用前的需求估算，不是新训练授权。适用范围是当前 MuJoCo CPU 环境＋SB3 PPO，一次运行一个训练任务；不包含迁移到 Isaac Lab/mjlab GPU 批量仿真的成本。

**当前决定：用户随后选择暂时使用本机，并接受更慢训练。服务器暂不租用；本文保留为将来的规格与费用估算。** 本机下一方案先评估 4 环境，必要时在正式训练前选择 2 环境，资源预检和新预算另行定义。

## 建议的起点

| 项目 | 首次比较的配置 | 理由 |
|---|---|---|
| CPU | x86-64，16 vCPU，性能稳定的计算型/通用型 | 现有 8 环境＋主进程；vCPU 数不等于物理核心数，也不保证吞吐高于本机 |
| RAM | 32 GiB | 给训练与依赖、操作系统和评测留下余量；单任务试运行后以实际峰值修正 |
| 存储 | 约 100 GB SSD 工作空间 | 为系统、Python 依赖、模型资产与新日志预留；不是当前源码体积或最低必需量 |
| GPU | 当前方案不要求 | 冻结训练器明确 `device=cpu`；GPU 显存不能代替主机内存 |
| 系统 | Ubuntu 22.04 x86-64；Python 3.10 | 接近已记录环境，仍须核对库、二进制和绝对路径 |
| 计费 | 首次按量/按小时，先验收再决定长租 | 现有吞吐不能直接外推到未知主机 |

例如阿里云当前规格表中 `ecs.c8i.4xlarge` 为 16 vCPU／32 GiB；这里只作为规格例子，未核定地域、库存或购买页报价。[官方规格表](https://help.aliyun.com/zh/ecs/user-guide/overview-of-instance-families)

持续高负载训练不优先选择依赖 CPU 积分的突发型；共享型也需关注性能波动。它们不是与稳定计算型等价的“同核数”资源。[突发性能说明](https://help.aliyun.com/zh/ecs/user-guide/burst-performance-instance-overview)、[共享型说明](https://help.aliyun.com/zh/ecs/user-guide/shared-instance-families)

AutoDL 是可比较的另一种平台，但不要把“无卡模式”当作廉价多核 CPU 服务器：其官方公开配置是 0.5 核／2 GB。若比较正常 GPU 实例，应比较附带的 CPU、内存、总小时价，而非仅看 GPU 型号；本项目当前不因 GPU 更贵而自动加速。[无卡模式](https://www.autodl.com/docs/save_money/)、[计费说明](https://www.autodl.com/docs/price/)

## 时间与费用怎么算

合同 10 本机已实测约 1,256 transitions/s，但因 RAM 门只完成 3,879,424 transitions。该速度是本机历史观测，不是服务器承诺，也不证明训练可以稳定完成。

以下以 8,388,608 transitions 作为算量参照，计算 `transitions / 吞吐 / 3600`；不包含预检、导出、评测、传输和环境安装，且不代表下一合同一定沿用此预算。

| 服务器实际吞吐 | 纯训练时间 |
|---:|---:|
| 500 transitions/s | 4.66 小时 |
| 1,000 transitions/s | 2.33 小时 |
| 1,500 transitions/s | 1.55 小时 |

费用应按选定地域与实例的实际报价计算：`开机时长 × 实例单价 ＋ 存储/网络等费用`。例如**假设**实例为 3 元/小时、开机 5 小时，则实例部分为 15 元；这是算式示例，不是市场报价。租用后应核对平台关机与持久存储的实际收费规则，不能把程序退出当成实例停费。

## 正式训练前的验收

1. 先核对实际 CPU 配额/亲和性、内存与 cgroup 限制、磁盘容量、架构和网络。主机显示的总量不等于容器获配量；不靠 swap 达到 RAM 资源门。
2. 恢复有来源的代码和所需模型资产，核对 SHA。仓库 clone 不包含全部第三方模型、权重或运行库；不把本机整个 home 或凭据复制过去。
3. 对照[依赖记录](../training/DEPENDENCIES03.md)和原 `protocol.json` 核验版本。当前记录含 MuJoCo 3.3.0、Gymnasium 1.2.0、SB3 2.7.0、PyTorch 2.12.1+cu130，但 PPO 使用 CPU。替换 PyTorch 构建或其他依赖也属于环境变化，不能直接沿用旧等价性结论。
4. 先运行不加载机器人、不推进物理的静态检查，以及标准库 IPC 检查。当前硬编码路径涉及 `/home/lyh/ddt_ros2_ws`，更换账户/前缀需在新配置中处理，旧冻结输入不改。
5. 真正的机器人吞吐基准与 E0 都消耗物理预算，须写入下一合同；不以“服务器测试”为名免费执行。先确定新的单变量方案、额度、资源门和中断规则，再启动一次正式训练。

迁移到不同 CPU、库或并行数后，固定 seed 不保证逐步相同。若事前约定的等价检查不通过，应如实判定；不临时放宽阈值以继续训练。是否支持故障后恢复也应事前定义，不能恢复合同 09/10 或把它们的未消耗余额带到服务器。
