# 76：分开解释响应方向与小梯度资格

`numeric_valid` 是多个旧门的合取，不能单独解释为数值稳定或不稳定。新入口 `tools76/readback76.py` 只读取已完成的72存档，生成完整 JSON、逐行 CSV 和摘要；不加载模型、数值计算库或环境。

固定覆盖三个 seed 的两臂：378条H32自检记录（含development）、216条H1、1728条body响应、864条yaw响应，共3186条标量记录、4050项已保存自检。全部旧点与四档ε保留。没有记录的conditional yaw JVP和H32扰动端点明确标为缺失，不能用另一条计算路径替代。

诊断独立报告：

- 自动微分/差分绝对差、原容差及实际相对差；容差通过不意味着相对误差小。
- 导数是否达到原`1e-5`幅值门、自检是否反号或为零；低幅值不等同于算术不一致。
- 物理参考是已解析、未知还是未记录；未知不能被表面异号重新判为错误。
- 模型/物理的原始符号、具备已记录自检资格后的匹配，以及原有效匹配结果。三者分别保存。
- 相同导数坐标中的模型/真实响应比；物理未知或真值为零时不计算比例。
- 已存F64端点的精确分数差商、最后减除的舍入差，以及各端点移动一个相邻F64值后的敏感区间。该区间不是模型全计算链误差界，也不是新的通过门槛。

运行方法：

```bash
python3 -B tools76/readback76.py --output evidence/response_diagnostics76/readback_01
python3 -B -m unittest discover -s tests -p 'test_*76.py' -v
```

输出目录必须不存在。工具核对发布清单中的原文件大小和SHA，结束时重新核验输入及源码；失败保留已读前缀并输出INCOMPLETE。CSV每行携带原始JSON指针，完整物理参考及其四尺度/单边资格保留在JSON中。先检查`status`和`verification_after`均为COMPLETE，再使用摘要。

本次是轻量存档日志诊断，不是新模型对照：模型调用、训练更新、actor调用和物理步均为0；75候选及其资源准入、预算、冻结源和原资格不变。诊断结果不能作为新的训练或运控性能结论。

## 执行结果

完整读回及结束核验均为 **COMPLETE**：650个输入文件、3186条记录，CPU **0.921秒**、墙钟1.257秒、峰值RSS **72.15MiB**。这是标准库文件诊断；没有启动受资源门约束的模型/训练/仿真任务。28项标准库单元测试和Ruff通过。

| 结果 | 数量与解释 |
|---|---|
| 原AD/FD容差满足 | 4050/4050；自检反号0 |
| 原方向资格失败 | 123项：60条body记录各两项自检，加3条H1；均为同号但低幅值，不是123个独立点 |

| 未记录的证据 | 864条conditional yaw没有JVP自检；另54条development H32没有正式物理参考 |

2808个可读端点差商全部逐位复现保存的FD。70条低幅值记录的端点间隔最小仍为 **1,984,680个合计ULP**；保存FD相对已存端点精确差商的最大绝对差为 **2.02×10⁻²²**。把每个端点移动一个相邻F64值，70条均不跨零或原±1e−5幅值边界。该证据说明这些记录的最后减除运算、存储端点分辨率不足以解释低幅值失格；它不能证明模型上游计算无误，也不能把模型响应偏差归为已解决。
