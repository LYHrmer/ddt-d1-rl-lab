### G4 为什么策略会选择抖振：被测量不可观测

57 维观测（`training/d1_rl/interface.py:81-85`）= 滤波陀螺×0.25 (3) + 机体重力方向 (3) + 命令×[2,2,0.25] (3) + 关节偏移 (16，**轮项强制为 0**) + 关节速度×0.05 (16，含轮) + 上次动作 (16)。

**没有基座位置，也没有基座线速度。** 历史只有 10 帧 × 20 ms = 200 ms，无法重建 4 秒前设下的锚点位置。

因此 04a 要求最小化的 ‖xy − anchor_xy‖ **对 actor 不可观测**。PPO 学不到位置调节策略，只能找到最好的**无记忆**替代：高频抖振，使时间平均位置停在原地而不需要知道锚点在哪。这解释了 G2 与 G3 的全部组合 —— 位置目标通过"减小净偏置"这唯一可观测通道得到了改善，抖振是副产品。

## 2. 唯一可证伪假设

> **假设**：03d 的恒定轮偏置与 04a 的 12 Hz 抖振，都是"零命令时轮动作不为零"的两种表现（G7）。按 G6 的接口算术，零轮动作是纯阻尼，刹停距离 0.0383 m 且停稳后无漂移，**同时满足 0.05 m 位移门与 0.02 m/s 末秒速度门**。对零命令段的四个轮动作均方幅值施加惩罚，其唯一最小点就是 a=0；且这个被测量**对 actor 完全可观测**（就是它自己的输出），因此不存在 04a 那种"目标不可观测 ⇒ 退化为抖振"的失效路径（G4）。

选择它而非"累计路径长度"的理由：路径长度的最小化者要求策略把 \|v\| 压到 0，而 57 维观测中没有线速度，只能经轮关节速度间接推断（实测存在约 8 % 滑移）；轮动作幅值是策略自己的输出，无需任何估计。

**不预测、不声称的事项（写在前面以免事后包装）**：

- 本合同**不预期达到 3/3**。turn_stop 同时被 wz MAE（03d 0.1029、04a 0.1118，门槛 0.08）卡住，本改动在非零转向命令期间**完全不生效**，不预测修复它。预期最好 **2/3（forward + reverse）**。
- 不声称修复 4–8 s 倒退跟踪缺口、`FL_calf` 钳位、地形通过、持续侧移或 1.5 m/s。
- 回报上涨、跨语言数值一致、训练 COMPLETE、没有跌倒，**均不等于控制资格通过**。

## 3. 冻结的唯一改动

新增 `training/d1_rl/task04b.py`、`training/configs/pilot04b.json`、`training/d1_rl/factory04b.py`。**03d 的命令调度、既有奖励项与权重/尺度、actor 接口与历史、观测、动作尺度与限幅、时基、reset、termination、PPO 全部不变。** 不引入 teacher、行为克隆、旧权重热启动、真值线速度观测、PID、动作后处理。**不继承 04a 的锚定位移项**（静态检查有专项断言）。

```
仅当 interval_command 的 vx 与 wz 同时为 0 时生效
（与既有 standstill_tracking 的门控条件逐字相同）

a_wheel := 本 tick 已裁剪的 issued action 的第 3/7/11/15 维
raw     := min( mean(a_wheel²), saturation )     saturation = 0.25
贡献/秒  := raw × weight                          weight     = -10.0
```

实测代价（静态回执 `wheel_action_penalty_table`）：

| 行为 | mean(a²)/tick | 贡献/秒 |
|---|---:|---:|
| 理想 a = 0 | 0 | **0** |
| 03d reverse 实测 | 0.05481 | −0.55 |
| 03d forward 实测 | 0.06516 | −0.65 |
| 初始化（log_std_init = −1） | ≈0.135 | −1.35 |
| 04a turn 实测（抖振） | 0.17363 | **−1.74** |
| 饱和上限 | 0.25 | **−2.50** |

设计理由：

- `saturation = 0.25` 置于**整个实测区间之上**（最大实测 0.174，初始化 0.135），保证训练全程梯度不平。最初设的 0.09 会把 04a 与初始化都放进平区，**这个缺陷被静态检查 `gradient_live_over_the_measured_range` 在训练前抓住**（失败回执 `task04b_static_01`）。
- `weight = -10.0` 使最坏惩罚 **2.50 /s** 低于零令时的正向底板（`vx_tracking + wz_tracking + alive ≈ 4.04 /s`），余量 1.54 /s，**避免"主动跌倒结束 episode 比站着漂移更划算"的反向激励**；该不等式既是静态检查项，也在 `_validate_config` 中强制。
- 惩罚方向与既有 `standstill_tracking` 一致（a→0 同时使蠕动→0 使该项取满），**不存在内部冲突**。

训练与评测入口为通用注入器 `tools04/run_frozen_entry.py --factory d1_rl.factory04b`：它不复制也不修改冻结的 `tools/train_d1_ppo.py` 与 `tools/evaluate_d1_ppo.py`（先校验两者 SHA256 等于 03d release 记录值），再以 `runpy` 作为 `__main__` 执行。因此全部超参、预算上限、计数器、source snapshot 与回执仍由冻结脚本产生。`factory04b` 以委托链扩展 `factory04`，**不修改**后者（其 SHA 已写入 04a 冻结回执）。
