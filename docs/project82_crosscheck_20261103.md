# 82：接口修复与控制证据交叉核对

本轮新增了可运行的原生适配核心，并对已有完整轨迹、四尺度响应及两仓控制证据作独立复核。**原生核心测试通过；没有取得新的策略性能或ROS部署资格。** 默认25/34策略不变，81的失败结论保留。轮侧另执行一次输入延迟MPC对照，完整但被原门槛拒绝。

## 已实现并实际测试的工程改动

[runtime82](../runtime82/README.md)是独立C++17核心和明确使用合成动作的可执行探针，没有改旧ROS/FSM、34或模型权重。它提供以下行为：

- 按25/34构造当前57维加旧10帧的627维输入，动作先裁剪；腿倍率0.5、轮倍率5，保留对应PD增益。
- 显式effort输出，腿/轮双向限幅分别为80/12 Nm；有限大数在转换成float前检查范围。
- 冷启动和热重入清除历史、滤波、动作和请求状态；generation/sequence拒绝跨重置的迟到响应。
- 单调时钟核验，响应超过20ms、命令年龄超过本入口明确规定的500ms、非有限值或时钟回退时锁存故障。故障输出没有位置目标，避免将零动作误作默认姿态PD。

原生检查实际通过**11,256项断言**，覆盖12帧非平凡历史顺序、全部39个传感器通道的非有限值、float边界、双向力矩限幅与时间边界。标准库驱动在本机5/5通过；不带本机供应商源码和旧工件的干净源码副本为3通过、2项本机历史证据检查明确跳过，核心检查全部执行。首次与最终日志分别保存，未覆盖。新[CI](../.github/workflows/adapter82.yml)在Python3.10/3.12编译并调用原生核心。

这解决的是**新核心中的接口和生命周期缺陷**。旧ROS默认入口没有被接管，核心尚未连接真实34推理进程、DDS或硬件；20ms年龄门不等于50Hz调度或250Hz PD实现。未来wrapper在reset时还必须重建34的参考整形会话。等待响应/故障时零effort没有物理停稳、制动或直立保证，也不能替代硬件watchdog。原ROS倍率、热重入、无效clamp及硬件失败处理的旧问题，不能写成已经部署修复。

奇偶分解是有限端点恒等式，偶项可能包含动力学、舍入、夹紧及abs/max变化，不把它命名为已证实的曲率原因。D的ideal-F64端点与V的actual-F32端点来自不同状态，没有同条件精度干预，更没有F64物理结果。三个模型共用三个环境reset，不能当九个独立环境seed。

## 完整任务：方向和任务之间的取舍

读回63个完整H回合的37,800行，46,724项检查通过，原J重算最大差5.55×10⁻¹⁷。[全部时间归因](assets/project82/time_error82.json.gz)使用固定时间窗，属于事后描述，不改变原判定。

- Q6相对原actor的前进任务J在**9/9配对均增加**；三模型均值增加0.000604/0.000391/0.000544。主要损失位于3–8秒前进跟踪。
- 正转向3–5秒偏航MAE分别增加0.0001312/0.0001183/0.0000433 rad/s，负转向6–8秒则下降。C6也出现这种符号间取舍，不能单独归因于Q6的max算子。
- V中Q6优于C6，H中相同175/325起点的32拍时段已变为Q6较差；不只是把32拍扩成完整稳态窗口后才反转。V/H同时改变reset组和此前策略历史，尚不能分离两者原因。
- 63/63回合issued与applied动作数值相同，轮动作到达±1及已记录力矩饱和次数均为0。这只约束本轮无注入延迟的H，不能推广到硬件，也不证明所有pre-clamp事件均有独立记录。

因此，补critic不能自动解释同32拍排序反转；继续降低状态预测误差也不能替代实际策略方向的响应验证。跨任务保护、响应幅值与持续执行后的状态/历史仍未解决。完整H缺45维状态及627维逐拍输入，不能用现有紧凑日志补出完整反事实。

## 论文方法采用边界

[SuperMimic](https://arxiv.org/pdf/2610.28480)的速度接口输出32维任务latent，经共享decoder生成全身动作；本仓627→3模块是速度估计器。按同名encoder直接解冻并不等价于论文方法。论文中速度奖励不更新decoder，decoder仍接受motion-tracking训练，不能概括成全程永久冻结。

[DMO](https://arxiv.org/pdf/2509.00215v2)使用真实前向状态、模型局部反向导数；旧55的CenteredModel在固定anchor处已经具有同类结构。当前策略方向可以成为新的诊断对象，但不能把换一个方法名称当成尚未尝试的修复。更详细的原文位置、官方实现与本仓对应关系见[论文交叉笔记](project82_literature_20261103.md)。本轮没有据论文追加GPU并行训练或模型更新。

## 两仓结果与未解决项

轮侧[MPC、估计器和PI交叉验证](https://github.com/LYHrmer/wheel-legged-control-lab/blob/main/docs/project82_control_20261103.md)：新MPC只补两拍预测FIFO，12回合完整、4,800控制拍/48,000积分步；高度RMSE增加0.047%、速度RMSE增加7.65%、pitch RMSE增加16.50%，原门拒绝。输入队列修复正确不等于失配控制效果改善。

PI已有条件积分抗饱和；离散原参考精确逐拍跟踪所需力矩在50.4%样本的绝对值超过2Nm，峰值2.904487Nm，不能靠任意缩小前馈消除此约束冲突。该结论仅适用于已知合成台架，不是实机辨识或RMSE下界。当前49/50估计器对照仍分别恶化16.84%/18.66%，其配对子集不同；历史17/36跌倒不再被当成当前源码的新验证。

仍待解决：真实ROS/硬件适配与停令验证、估计器闭环时序一致性、失配MPC的静态模型偏差、PI约束下的跟踪取舍、策略跨任务改善，以及50中断后未回答的三seed训练统计问题。没有新增训练来掩盖这些缺口，48未重跑，50未续跑。
