# 合同 08：训练规模是不是 03d 的瓶颈

**状态：已登记，待由 release 回执冻结；未执行。** 冻结之后本文的预测、阈值、预算与停止规则不得修改，修改须新建合同。2026-10-16 由用户授权开启并给出训练预算。

## 1. 要回答的问题

五个自训版本的平地低速资格都没有通过（0/3、0/3、1/3、0/3、0/3）。合同 04 的两次奖励改动与合同 05M 的物理测量都没有找到一个能单独解决问题的奖励杠杆。同时有一组被反复看到、但从未被检验的事实：

- 每次训练只有 1,048,576 transitions（03d 用时 795 s）；
- 03d 与 04b 的训练回报到最后 25 % 仍在上升（+10.3 %、+12.1 %，回执 `training_ledger_comparison_01`）；
- 04b 的驱动相平台、03d 的 turn wz MAE 0.103 都可能只是"还没学完"。

**本合同只问一件事：在 03d 的配置下，把训练步数放大到 8 倍，资格是否改善。** 不改奖励、观测、动作、网络、超参、种子、环境数，只改步数。

## 2. 为什么选 03d

03d 是五个版本里最好的（1/3），且没有合同 04 引入的任何额外奖励项。放大它，回答的是"现有设计在更多训练下能走多远"，结果不会和某一项新奖励的效果纠缠在一起。

## 3. 先决事实与新入口

冻结的 `tools/train_d1_ppo.py` 把 pilot 的单次上限写死为 1,048,576 步、种子 101，且不允许续训；`formal` 允许 4,194,304 步但要求已通过资格，不可用。PPO 的学习率 3e-4、clip 0.2、熵系数 0.005 都是常数，没有随总步数变化的调度，`max_transitions` 只是一个硬上限，不影响仿真。所以**从同一种子出发，8 倍训练的前 1,048,576 步应当与冻结的 03d 训练逐位相同**。

新入口 `tools08/train_d1_ppo08.py` 是冻结脚本的**逐字节副本，只改 3 行**：`--kind` 增加 `scale`；`limits` 增加 `"scale": (8388608, 9000)`；`scale` 与 `pilot` 一样要求种子 101。选择复制而不是 import，是因为这样 `make_env` 仍定义在 `__main__` 里，子进程的序列化路径与冻结脚本完全相同。静态检查逐行核对差异恰好是这 3 行。

导出（`tools/export_d1_ppo.py`）与评测（`tools/evaluate_d1_ppo.py`）都用冻结脚本，不改。导出器只接受计划步数等于实际步数的完整训练目录，所以**只能、也只会评测最终策略**，中间 checkpoint 不存在、不评测。学习曲线只看训练台账。

## 5. 门槛与预注册预测

**E0 预检等价性（训练之前）**：新入口以 `--kind preflight --steps 32768` 训练，其前 8 个 rollout 的 `reward_contribution_mean_per_tick` 与 `actual_counts` 与冻结 03d 台账的前 8 行逐项相等（浮点相对差 ≤ 1e-9，计数完全相等）。不满足 ⇒ **不启动正式训练**。此时用冻结脚本跑同样的预检做诊断：若冻结脚本自己也对不上，说明流水线本身不确定，合同终止并记录；若冻结脚本对得上，说明新入口有差异，合同终止。

**E1 正式训练等价性（训练途中）**：正式训练的前 256 个 rollout 逐个与冻结台账比对，标准同 E0。旁路监视器 `tools08/watch_equivalence08.py` 一旦发现不符，立即向训练进程发 SIGINT，训练按冻结脚本的异常路径保存 `partial_policy.zip` 并写回执，**合同终止，不导出、不评测**，已消耗的步数如实计入。

**资格判定（只评测最终策略，冻结评测器，三条任务，seed 7001，delay 0）**，基准是 03d 1×：

| 编号 | 类型 | 预测 | 03d 1× 基准 | 判定 |
|---|---|---|---|---|
| **P1** | 主判据 | 8× 策略通过的任务数 ≥ 2 | 1（只有 reverse_stop） | ≥ 2 ⇒ 支持"训练规模是瓶颈之一"；≤ 1 ⇒ 推翻"8 倍训练足以改善资格" |
| **P2** | 次判据 | forward_stop 停车位移 < 0.05 m | 0.081 | — |
| **P3** | 次判据 | turn_stop 稳态 wz MAE < 0.08 rad/s | 0.103 | — |
| **P4** | 描述 | 训练回报末 25 % 的相对变化（只报告，不判定） | +10.3 % | 若仍 > +5 %，说明 8 倍也没有收敛 |
| **P5** | 不回归 | 8× 的 reverse_stop 仍然通过 | 通过 | 不满足 ⇒ 放大训练使已有能力退化 |

**事前声明不预测**：是否达到 3/3（不预期）；C++ 部署一致性（只做 0 物理步的黄金比对，见 §7）；地形、侧移、高速。

## 7. 停止规则

- 顺序固定：静态检查 → release 冻结回执 → E0 → 正式训练（E1 监视器同时运行）→ 导出 → 黄金比对 → 资格评测 → 判定回执。
- 每一步各只执行一次，不重试、不换种子、不续训、不挑 checkpoint、不调参重跑。
- 训练因 wall 上限、RAM 门或 E1 中止，都如实记录为结果；不完整的训练不导出。
- 任何结果都**不授权**正式三臂×三 seed，也不授权把单条任务通过写成资格通过。

## 8. 结果的使用边界

- 单种子（101）、单配置（03d）、仅平地、Python 评测器决定资格。
- P1 成立只说明"在这个种子下，8 倍训练让资格变好"，不证明规模是唯一瓶颈；P1 不成立只说明 8 倍不够，不排除更大的规模有用。
- 不改变五个已有版本的资格结论。
